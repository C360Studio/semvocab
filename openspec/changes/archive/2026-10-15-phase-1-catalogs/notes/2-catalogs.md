# Notes: tasks 2.1–2.3 (catalogs)

## API shape

- `SubClassOf` is a function, `SubClassOf(iri) (parent string, ok bool)`, not SemStreams' exported
  `map[string]string`. An exported map can be written by any importer, which would corrupt the hierarchy for the
  whole process. Consumers moving from SemStreams change `bfo.SubClassOf[x]` to `bfo.SubClassOf(x)`.
- A single parent suffices: every admitted BFO and CCO class has exactly one asserted named `rdfs:subClassOf` parent
  in its release, and every parent is itself in a catalog. `TestCatalogHierarchyMatchesRelease` fails if the
  release ever asserts two.
- `cco.SubClassOf`, `cco.Parents`, and `cco.IsA` cross into `bfo`: on a BFO IRI they answer as `bfo` does.
- `ImmaterialEntity` is the Go name chosen for the ledger's external addition `BFO_0000141` ("immaterial entity");
  the ledger names the term but not a Go symbol.
- `bfo.RealizedIn` (`BFO_0000054`) keeps SemStreams' name; BFO 2020 labels it "has realization". The doc comment
  says so. The meaning matches (realizable entity to process); the ledger admits it.
- The `cco` constants were generated once from the ledger table and are checked against it and against the release
  file; the `cco` doc comments carry each v2.2 label.

## Oracles and recorded command

- `internal/turtle` is the test-only reader (P4). Beyond what the two release files use it reads `a`, `_:` labels,
  and numeric and boolean literals, because `TestDirectSerialization` parses SemEngine's Turtle and N-Triples output
  with it. It rejects relative IRIs, single-quoted strings, SPARQL-style directives, and local-name escapes, naming
  line and column. Its tests use W3C Turtle Recommendation examples.
- `internal/gosrc` type-checks a package's source with `go/types`, so the parity tests check the constants the
  package actually exports, not a hand-written table.
- The SemStreams parity fixture `catalog/bfo/testdata/semstreams-bfo.txt` is generated by
  `scripts/gen-semstreams-fixture.sh <semstreams clone>`: `git show <pin>:vocabulary/bfo/{bfo,hierarchy}.go` into a
  temporary directory, then `go run ./internal/tools/semstreamsfixture`, which evaluates the constants with
  `go/types` and reads the `SubClassOf` literal. The fixture records the pin and the sha256 of both source files.

## Shown able to fail (seeded in the package, then reverted)

- `bfo.Site` set to `BFO_0000092` and its parent to `IndependentContinuant`: `TestCatalogPortParity` reports the
  SemStreams mismatch and the undeclared IRI; `TestCatalogHierarchyMatchesRelease` reports the closure, `IsA`,
  `SubClassOf`, and the BFO_0000141 scenario.
- `cco.Altitude`'s parent set to `OneDimensionalExtent`: `TestCatalogHierarchyMatchesRelease` reports the closure,
  `IsA(Altitude, Height)`, `SubClassOf`, and the D5 Altitude closure.
- Permanent sensitivity tests: `TestCatalogPortParitySensitivity` (both packages),
  `TestCatalogHierarchySensitivity` (bfo runs the check on SemStreams' own map; cco drops one ancestor).
